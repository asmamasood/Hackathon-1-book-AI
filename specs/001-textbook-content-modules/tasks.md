# Tasks: Textbook Content Modules

**Input**: Design documents from `/specs/001-textbook-content-modules/`
**Prerequisites**: plan.md (required), spec.md (required for user stories), research.md, data-model.md, contracts/

**Tests**: No explicit test requirements in specification. Tasks focus on content creation and validation.

**Organization**: Tasks are grouped by user story (module) to enable independent implementation and testing of each module.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies)
- **[Story]**: Which user story this task belongs to (e.g., US1, US2, US3, US4)
- Include exact file paths in descriptions

## Path Conventions

- **Docusaurus content**: `docs/0X-module-name/` at repository root
- **Static assets**: `static/img/` (diagrams), `static/code/` (code bundles)
- Configuration: `docusaurus.config.js`, `sidebars.js`, `package.json`

## Dependencies & Execution Order

### Phase Dependencies

- **Setup (Phase 1)**: No dependencies - can start immediately
- **Foundational (Phase 2)**: Depends on Setup completion - BLOCKS all modules
- **Modules (Phase 3-6)**: All depend on Foundational phase completion
  - Module 01 (Phase 3): Can start after Foundational - No dependencies on other modules
  - Module 02 (Phase 4): Can start after Foundational - Independent (recommends Module 01 complete for URDF knowledge, but not blocking)
  - Module 03 (Phase 5): Can start after Foundational - Independent (recommends Module 02 complete for simulation knowledge, but not blocking)
  - Module 04 (Phase 6): Recommends all prior modules complete for capstone context, but technically independent for content creation
- **Polish (Phase 7)**: Depends on all desired modules being complete

### User Story Dependencies

- **Module 01 (P1)**: Can start after Foundational (Phase 2) - No dependencies on other modules
- **Module 02 (P2)**: Can start after Foundational (Phase 2) - Independent content creation (pedagogically builds on Module 01)
- **Module 03 (P3)**: Can start after Foundational (Phase 2) - Independent content creation (pedagogically builds on Module 02)
- **Module 04 (P4)**: Can start after Foundational (Phase 2) - Independent content creation (pedagogically synthesizes all prior modules)

**Note**: While modules are pedagogically sequential (learners complete 01 → 02 → 03 → 04), content authors can create module pages in parallel after Foundational phase is complete.

### Within Each Module

- Index page before detail pages (establishes learning objectives)
- Concept pages before hands-on pages (theory before practice)
- Hands-on pages before checkpoint (practice before validation)
- Code bundles can be created in parallel with pages
- Diagrams can be created in parallel with pages
- Checkpoint page must reference all prior pages in module

### Parallel Opportunities

- **Phase 1 Setup**: T002-T007 can run in parallel (different config files)
- **Phase 2 Foundational**: T009-T012 can run in parallel (different files)
- **Phase 3 Module 01**: T015-T017 (concept pages), T021-T024 (assets) can run in parallel
- **Phase 4 Module 02**: T030-T032 (concept pages), T036-T041 (assets) can run in parallel
- **Phase 5 Module 03**: T047-T049 (concept pages), T054-T060 (assets) can run in parallel
- **Phase 6 Module 04**: T066-T068 (concept pages), T073-T079 (assets) can run in parallel
- **Phase 7 Polish**: T083-T088, T091-T092, T094-T095 can run in parallel (different files)
- **All Modules (Phase 3-6)**: Can be worked on in parallel by different authors after Foundational phase

## Implementation Strategy

### MVP First (Module 01 Only)

1. Complete Phase 1: Setup
2. Complete Phase 2: Foundational (CRITICAL - blocks all modules)
3. Complete Phase 3: Module 01 (ROS 2 Foundation)
4. **STOP and VALIDATE**: Test Module 01 independently (learners can create Hello Robot node, build bipedal URDF)
5. Run `npm run build` and verify zero errors
6. Deploy to GitHub Pages and share live Module 01

### Incremental Delivery

1. Complete Setup + Foundational → Foundation ready
2. Add Module 01 → Test independently → Deploy (MVP! Learners can start learning ROS 2)
3. Add Module 02 → Test independently → Deploy (Learners can now learn simulation)
4. Add Module 03 → Test independently → Deploy (Learners can now learn AI perception)
5. Add Module 04 → Test independently → Deploy (Complete curriculum with capstone)
6. Each module adds value without breaking previous modules

### Parallel Team Strategy

With multiple content authors:

1. Team completes Setup + Foundational together
2. Once Foundational is done:
   - Author A: Module 01 (T013-T027)
   - Author B: Module 02 (T028-T044)
   - Author C: Module 03 (T045-T063)
   - Author D: Module 04 (T064-T082)
3. Modules complete and integrate independently
4. Polish phase (T083-T096) completed collaboratively
